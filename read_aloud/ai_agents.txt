Let me walk through where agent tooling actually stands right now, and where the hard parts are hiding.

Start with a narrow definition. An agent is a language model placed inside a loop, given tools, and allowed to decide when to call them. That is the whole idea. The model reads a system prompt, decides that it needs a tool, emits a tool call, receives the result, and continues. Everything else in the agent literature is a variation on that loop.

The model layer has consolidated faster than anyone expected. OpenAI, Anthropic, and Google are the three labs shipping frontier models with serious tool calling. Anthropic ships Claude, Google ships Gemini, and OpenAI ships the model family that most people still call by its original name. Below the frontier there is a dense open weights tier. Meta released Llama, Mistral released a family of small European models, DeepSeek released a reasoning model that pushed inference costs down sharply, and Cohere focused on retrieval and enterprise search rather than chat. Alibaba ships open weights as well. The practical consequence is that model choice is now a cost and latency decision far more often than a capability decision.

Serving is where the money actually goes. Nvidia still supplies most of the training hardware, but inference has fragmented. Groq built custom silicon for low latency decoding, and the name is a constant source of confusion with Grok, which is a completely different product from a completely different company. Ollama made local inference trivial on a laptop, which matters more than it sounds, because a developer who can run a model locally iterates ten times faster. Hugging Face remains the distribution layer for weights, datasets, and evaluation harnesses. Perplexity built a search product on top of other people's models and proved that the application layer captures real value.

Now the retrieval question. Retrieval augmented generation, usually shortened to RAG, is the pattern where you fetch relevant documents and paste them into the context window before the model answers. RAG solved the freshness problem and it solved part of the grounding problem. It did not solve hallucination, and anyone who tells you that RAG eliminates hallucination has not measured it. The retrieval step needs an embedding model, a vector database, and a chunking strategy, and the chunking strategy is almost always the part that is wrong.

Anthropic published the Model Context Protocol, usually called MCP, to standardize how a model discovers and calls external tools. Before MCP, every integration was bespoke. A protocol layer means a tool server written once works against any client that speaks the protocol. That is a boring infrastructure win, and boring infrastructure wins are the ones that stick.

Adaptation is the other axis. Full fine tuning is expensive and mostly unnecessary. Low rank adaptation, written as LoRA, freezes the base weights and trains a small pair of matrices instead, which cuts the memory cost by an order of magnitude. Quantization takes the trained weights and reduces their precision, trading a small amount of quality for a large amount of throughput. Distillation trains a small model to imitate a large one. Each of these is a different point on the same cost quality curve, and teams routinely reach for fine tuning when quantization would have been enough.

The failure modes are worth naming precisely. Agents fail when the tool description is ambiguous, so the model calls the wrong tool. They fail when the context window fills with tool output and the original instruction scrolls out of attention. They fail when a tool returns an error and the model retries the identical call forever. They fail silently when the model fabricates a plausible tool result rather than admitting the call failed. Guardrails catch some of this. Better tool design catches more of it.

Evaluation is the genuinely unsolved part. Chain of thought traces are easy to read and nearly impossible to score automatically. Task success rate is the honest metric, but building a task suite that reflects real usage takes longer than building the agent. Most published agent benchmarks measure something narrower than they claim, and the gap between benchmark performance and production performance is the single most reliable finding in the field.

If you take one thing away, take this. The loop is simple, the models are commoditizing, and the difficulty has migrated entirely into tools, context management, and measurement. That migration is why an agent that demonstrates beautifully can still fail in production, and why the teams that invest in evaluation early are the ones still shipping a year later.
